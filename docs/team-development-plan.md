# 动态 Agent 团队开发计划

目标：用户在项目内提出任务，选定的 Agent 有限讨论，按实际能力认领任务；平台处理冲突、依赖、权限与验收，而不是按产品名称固定岗位。

## 分工与交付顺序

1. **能力驱动分工（主对话）**：允许计划为步骤指定执行者、独立验收者；能力与接入权限检查不接受模型自报作为证明；保存分工原因。旧任务继续兼容。
2. **Harness 接入（「了解项目结构」对话）**：拥有 `worktogether/harness.py`、`tests/core/test_harness.py`、对应 fake 脚本、`docs/harness-adapter.md`。先确认本机真实协议，不混同 Hermes，不调用付费模型作为接口探测。该对话已恢复消息协作，正在开发适配器。
3. **有限讨论与认领（主对话）**：团队选择、并行只读首轮、精确步骤认领、冲突裁决与审计；默认不超过两轮，超出预算明确停止。不得将目前的逐个聊天伪称并行讨论。
4. **执行与验收（主对话集成）**：依赖就绪才派发；执行者不得验收自身成果；修复上限两次；暂停、重复结果、过期版本和崩溃恢复保持保护。没有隔离工作区前，写代码与验收仍串行。
5. **工作台与验收（共同）**：单入口显示团队、能力、认领、分配依据、进度和阻塞。完成自动化回归，再做用户授权的真实 Agent 端到端验收。

## 协作规则

- 两个对话共用目录，严格按文件边界编辑；主对话负责合并、回归和 Git 提交。
- 自动验收只证明协议与控制流程；真实模型尚未执行的能力必须明确标注。
- 普通 API 聊天不等于拥有终端、仓库编辑、浏览器或测试能力。
- CLI 存在不等于登录、配额、权限和实际执行可用。
- 保留现有实现并逐层替换，不另起一套无法迁移的原型。

## 最终交付门槛

- 三个不同 Agent 接入同一任务，真实读取彼此相关意见，有界收敛。
- 非 Codex Agent 在允许范围内完成实际工作，另一 Agent 独立验证。
- 认领冲突不会产生双重执行；跨项目、跨任务会话不串线。
- 暂停后不派新任务；重复点击不重复运行；恢复不盲目重放。
- UI 操作与后端状态一致，关键错误可理解；README 明示剩余限制。
- 所有代码回归通过；每个完成批次提交，不将模拟结果说成真实模型验收。

## 本轮进展

- 已完成能力分工、任务成员选择、两轮并行意见/认领、可变协调者、独立验收者和界面显示。
- 原有执行预算、方案批准、共享工作区写入互斥保持生效；一次授权的全流程自动执行与隔离工作树尚未完成。
- 两个对话以额度为停止依据：剩余可用额度超过 50% 时收尾暂停；未重置且仍可用则继续。凌晨两点不是硬截止，不使用重置券。
