# WorkTogether 现状与下一步（2026-10-11 修订）

## 目标与已实现的可用范围

目标是让一个项目中的多个 Agent 围绕同一任务讨论、分工、交付和验收，同时不干扰其他项目会话。岗位不再按品牌固定：任务团队可选择协调者，成员按实际适配器能力认领，平台校验唯一执行者与不同的验收者。

当前已实现任务团队、两轮并行意见/认领、三次集中规划、能力分工、独立验收、用户一次明确授权后的有界执行，以及原有的持久化、依赖、两次修复上限、暂停/重试与手动交接。新建任务页可一次提交启动团队；普通补充聊天仍依次回复，但跨任务可并行。Harness 后台适配器已实现，默认关闭，启用后可认领编码；API Agent 仅能规划、复核与分析传入材料，不能直接读仓库或运行测试。

本轮新增流程经模拟 CLI、假 HTTP 服务、真实浏览器操作验证；Harness CLI 帮助与权限配置合成经本机无模型探测。未进行本轮三种真实模型的完整交叉开发验收。详见 `team-workflow.md`、`harness-adapter.md` 和 `team-development-plan.md`。

## 已验证

- Python 单元与模拟协议测试，以及前端 TypeScript/Vite 构建。
- 本地测试页面：创建项目和任务、手动派发、读取交接包、拒绝无效 JSON 报告、提交模拟报告后进入下一阶段。
- HTTP 测试：验收阻塞后，显式重试产生新派发，手动提交有效验收报告可完成任务。
- 本机可发现 Codex CLI 和项目私有目录中的 Antigravity CLI；Antigravity 的只读模型列表包含默认的 `gemini-3.8-flash-high`。这不代表具体任务所需的工具授权已经验证。
- 隔离临时项目中真实执行：Codex 创建 `greeting.txt` 并报告与文件吻合的 SHA-256；Antigravity 初次使用终端命令时返回 `denied_actions`，平台拒绝验收。显式重试后，Antigravity 使用只读 `view_file` 核对确切内容，返回有依据的 PASS，任务进入 COMPLETED。这只覆盖简单文件检查，不代表可自动运行全部测试。
- 上述极小任务的真实用量：Codex 输入 56,663（其中缓存输入 39,680）、输出 435；Antigravity 首次失败输入 25,054、输出 1,688，第二次通过输入 58,827、输出 9,997。不同提供方的用量口径可能不同；这些数字足以说明当前流程**未证实节省 Token**，且首次权限失败带来显著额外开销。
- 调度器现按派发类型提供精简的模型指令，不再每次附上超过 7 KB 的公共 CLI/状态契约。一个最小 PLAN 派发的新指令为 1.7 KB（按 UTF-8 字节计）；这只是本地输入大小，不是模型 Token 或费用降幅。真实效果仍需同题、同环境对照测量。
- 自动 CODE/FIX → VERIFY 现对 Git 可见文件做交付与验收前后漂移检查；模拟测试覆盖修改后阻断和无变化通过。尚未用真实 Agent 验证这一保护，也未生成固定快照。手动交接、非 Git 目录、Git 忽略文件和并发竞态仍需单独解决。
- 自定义 OpenAI 兼容 Agent 可由用户主动发送一次不含任务内容的短请求来测试接口响应；注册和打开页面不会自动调用。该检查可能产生少量模型用量，只证明基本连接与聊天返回形状，尚未证明真实任务分工可用。
- 运行详情可按需查看五种受限产物（指令、结果、事件、错误和启动参数），大文件最多预览 512 KB；没有自动拉取完整日志或扩大文件读取范围。
- 本机回环假服务已完成真实 HTTP 闭环：连接检查、三 Agent 顺序讨论、API Agent 接收前两位回复、计划批准后的分析交付、Antigravity 验收和依赖 Codex 步骤。未访问外网或付费模型；这不是 DeepSeek/Ollama 实际可用性的证明。受限沙箱无法绑定回环端口时，该集成测试会明确跳过。

## 2026-10-11 补记：项目上下文与后台能力对齐

- 修复 `--db` 缺陷：`web` 子命令重复定义 `--db`，argparse 会用它自己的默认值覆盖子命令前传入的数据库路径，导致 `python3 -m worktogether --db /tmp/x web` 静默使用 `.collab/state.sqlite3`。已改为 `argparse.SUPPRESS` 并加参数回归测试。
- 对话派发现已自动携带**有界的项目上下文**（项目名、路径、README 前 3000 字、最多 120 个文件路径），并指示 Agent 可只读查看、不要声称没读过的文件。这是对“Agent 不知道自己项目在做什么”的直接修复。
- 项目记忆（本机数据库，最多 20000 字）、`@引用文件`（最多 10 个，单文件 12 KB、总 48 KB）、按消息授予的“允许修改”、1/2 轮发言、被中断回复的显式重试/跳过，均已从后端接到工作台 UI。
- 提供了有界文件清单、Git 状态与统一 diff 的只读接口，以及需二次确认的逐文件还原；这是**回滚便利**，不是版本隔离。
- Agent 档案可编辑（名称／描述／系统提示），自定义 Agent 可克隆本机 CLI 或接 OpenAI 兼容接口，API Key 可选存入状态库同目录的 `secrets.json`（权限 600，环境变量优先）。
- 任务与项目可重命名／删除；删除项目级联清理平台记录，存在在途运行进程时拒绝。
- 验证方式：`python3 -m unittest discover -s tests -q` 237 项通过（本轮新增 68 项：工作区上下文、项目与任务管理、Agent 档案与密钥、聊天上下文与消息解析、HTTP 路由、CLI 参数）；`cd web && npm test` 10 项通过；`npm run build` 通过。真实浏览器（1046×653）在临时数据库上核对：添加项目、打开项目上下文、保存并回读项目记忆、编辑并保存 Agent 系统提示、打开文件选择器选中 README、对 `codex` 缺失造成的 BLOCKED 消息执行“跳过”并确认只剩跳过占位。全过程未触发任何真实模型调用（`agy` 未参与）。

## 尚未达到的预期

1. **真实项目的无人值守闭环**：隔离样例已通过，但 Antigravity 的工具权限拒绝仍可能让需要运行命令的验收停止。平台提供手动交接与报告提交，不绕过权限，也不把隔离样例当作真实项目验收。
2. **任意本地 Agent 接入**：Harness 0.2.0-rc.2 适配器已实现，但真实登录、工具权限和模型交付仍待验收。Claude Code/ZCode 的原生 CLI 适配器未实现；OpenAI 兼容接口接入不能代替原生编码工具能力。
3. **安全并行编码**：没有隔离 worktree、固定被测提交和合并审查，不能让多个编码 Agent 同时修改同一目录。现阶段同一项目的 CODE/FIX/VERIFY 派发互斥，自动 Git 交付另有有限的漂移检测；不同项目仍可独立推进。新增的“允许修改”只按消息授予写入沙箱，**不**构成版本隔离；逐文件还原也不会保留被覆盖的改动。这不能阻止平台外的手动编辑，也不能替代真正的版本隔离。
4. **效率结论**：没有真实的单 Agent 与多 Agent 同题对照数据，因此不能承诺节省 Token、成本或时间。
5. **界面深度**：页面可展示运行记录、报告、限定产物预览、项目 Doctor、项目记忆与文件清单、Git 变更与逐文件还原；任意文件内容浏览、内置 CLI 的认证检测和可靠的用量对比仍未接入页面。

## 下一轮优先级

1. 使用用户明确指定的真实小任务，在不扩大工具权限的前提下检验代码修改与需要运行测试命令的验收；记录权限结果、实际用量和失败原因。若仍受阻，保持手动验收为可用路径。
2. 定义版本隔离和只读测试环境，避免验收时 Codex 的后续改动污染被测版本；再考虑分析与测试准备的有限流水线重叠。
3. 先做用户允许的 Harness 短小真实连通测试，再用临时项目验证非 Codex 编码与另一 Agent 验收；失败保留证据，不扩权绕过。随后按实际需求选一个其他 CLI 扩展，不把任意命令字符串暴露给 Web 注册接口。
4. 真实对比 Codex 单独完成与协作模式：记录任务质量、Codex Token、总耗时、人工介入次数和误报。仅根据实测结果调整分工。

任何新能力都应先有端到端证据，再更新 README 和界面中的“可用”描述。
