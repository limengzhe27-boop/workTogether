# 任务内对话 v1

POST /api/tasks/{task}/messages：{message_id, recipient, content}。
recipient 为 codex / antigravity / both；content 1–20000 字符。
返回 202 表示已保存，不表示模型已回复。相同 ID、相同内容幂等；不同内容冲突。
GET 同一路径返回 {messages:[...]}，持久保存用户文字、需求版本、回复与状态。

状态：QUEUED / RUNNING / DELIVERED / BLOCKED / NEEDS_REVIEW。
RUNNING 表示派发已认领，真实进程状态以 runs 为准。未知认领不自动重放。

服务内普通线程按秒检查队列，不调用模型做轮询判断；当前实现全局串行消费，
长回复会延迟其他任务消息。后续可做带并发上限的项目级消费者，不应无限增加线程。
角色和会话均由任务绑定，模型只能执行 CHAT 派发，复用对应任务的提供方会话。
双方模式为 Codex 回复一次 → Antigravity 参考首个回复再回应一次，不无限循环。
上下文带当前需求、方案、最近六条已完成消息；跨任务不共享。

运行中消息先排队，不强杀进程；待当前执行结束后再处理。有限规划在下一次派发时
检测到待处理消息即停止，规划作业显示 INTERRUPTED；回复后不自动重启规划。
暂停/阻塞期间只保存，恢复后才消费。已完成任务可继续讨论，不因此重新开发。
需求版本改变后尚未交付的旧版本队列标为 NEEDS_REVIEW，不悄悄套用到新要求。

CHAT 输出同 report envelope，DONE 的 data 为 {}，summary 为回复，suggestions 最多三条。
回复不是需求修订、不是方案批准、不触发代码执行。Codex 采用 read-only sandbox，
Antigravity 采用 sandbox + plan 模式并明确禁止工具与写文件；不把 plan 模式描述为
操作系统级只读保证。失败保留错误与派发记录，显式重试沿用原角色和消息。

UI：任务页“任务内对话”，默认 Antigravity，可切换 Codex/双方。
草稿按任务保存；发送会消耗所选提供方额度。消息投递和回复保存在当前任务，
不是共享桌面聊天窗口。连续多次发送可续聊，但不会自动执行聊天中提议的开发工作。

## 验证

- 71 项确定性测试通过：角色路由、双方两次回复、同会话恢复、去重、任务隔离、
  运行中排队、暂停、需求版本失效、失败不重试、未知认领不重放、完成后讨论、显式重试。
- 浏览器使用隔离测试库实际发送给双方，显示两条回复；刷新保留；暂停排队、恢复回复通过。
- 单次真实 Gemini 3.8 Flash High 对话成功；任务 8e7870fa192a4008a750a146ec37d5d8，
  证据 .collab/chat-live/state.sqlite3 及同级 runs/。本轮未新增真实 Codex 调用。
