# WorkTogether contract v1

Status: implementation contract, reconciled 2026-10-11. Python 3.9+, standard library only.
The HTTP inventory below and [room contract](chat-v1.md) describe current behavior,
not proof that a real provider is authenticated or can complete a task.
Production modules: `worktogether/`. Antigravity owns `qa/antigravity/` and
`tests/acceptance/antigravity/`; do not modify production modules to pass tests.

## Public CLI

All commands: `python3 -m worktogether --db PATH COMMAND ...`.
Output: one JSON object to stdout. Success exit 0; domain/input error exit 2 with
`{"error":{"code":"...","message":"..."}}`. No model is called implicitly.

- `project-add --name NAME --path EXISTING_DIRECTORY`
- `task-add --project PROJECT_ID --title TITLE --requirement TEXT`
- `show --task TASK_ID`: task, steps, dispatches, events (chronological).
- `dispatch --task TASK_ID`: issue at most one eligible work item. Returns
  `{"dispatch": object|null}`. Repeated calls never reissue active work.
- `submit --task TASK_ID --file REPORT_JSON`: atomically validate and ingest.
- `pause --task TASK_ID`; `resume --task TASK_ID` (only PAUSED).
- `retry --task TASK_ID --dispatch DISPATCH_ID`: explicitly retry BLOCKED dispatch;
  increments attempt, invalidates old dispatch. Not allowed at repair limit.
- `expire --task TASK_ID`: block expired ACTIVE dispatches; never auto-relaunch.
- `template --task TASK_ID --dispatch DISPATCH_ID`: output editable result JSON.
- `handoff --task TASK_ID --dispatch DISPATCH_ID`: task-scoped manual package,
  containing dispatch payload, report template and instructions.
- `doctor --project PROJECT_ID`: Git status, executable availability; no mutation.
- `demo`: isolated mock full cycle in this database; explicitly marked simulated.

Python public API: `from worktogether.core import Engine, CollabError`.
`Engine(db_path)`; methods `project_add(name,path)`, `task_add(project,title,requirement)`,
`show(task)`, `dispatch(task)`, `submit(task,report)`, `pause(task)`, `resume(task)`,
`retry(task,dispatch_id)`, `expire(task)`, `template(task,dispatch_id)`, `doctor(project)`.
IDs are opaque strings. API domain errors expose `.code`. Engine opens a transaction
per operation and supports independent instances against the same database.

## State and dispatch

Task status: ACTIVE, PAUSED, BLOCKED, COMPLETED. Task phase: PLANNING,
PLAN_REVIEW, PLAN_FINALIZE, EXECUTING, COMPLETED. One review round, then the
coordinator finalizes (Codex by default; cannot submit another review). Requirements
can be explicitly revised with an expected revision; old work is not silently reused.
Plan step: id, title, acceptance (nonempty string list), depends_on (step IDs).
Current extensions allow optional `work_kind: "code" | "analysis"`, `assignee`
and `verifier`. Assignments are checked against registered adapter capabilities;
the verifier must differ from the author. Defaults remain Codex / Antigravity.
Analysis may be assigned to ready Agents with `analysis` capability; this does not
give API Agents local tools. Normal web execution requires approval of the current
plan digest; explicitly authorized `delegate-team` is a separate bounded workflow.
Manual core dispatch does not itself launch a model or enforce the web approval gate.
The dependency graph must be acyclic. Finalization may edit the reviewed draft.

Step status: PENDING, CODING, ANALYZING, VERIFYING, FIXING, COMPLETED, BLOCKED.
Dependencies require COMPLETED. Until worktrees and pinned test environments exist,
CODE, FIX and VERIFY dispatches in the same project checkout are mutually exclusive,
including writable CHAT turns,
even across independent tasks; a blocked dispatch must be resolved or superseded
before another such dispatch can start. Different projects may proceed independently.
The report names a tested version, but v1 does not automatically make an immutable
workspace snapshot or prevent edits made outside the platform.

Dispatch: id, task_id, step_id|null, role (a registered capable Agent), kind
(PLAN|PLAN_REVIEW|PLAN_FINALIZE|CONSULT|CLAIM|CODE|ANALYZE|VERIFY|FIX|CHAT), attempt, version|null,
status (ACTIVE|DONE|BLOCKED|SUPERSEDED), created_at, deadline, payload.
Default timeout 1800 seconds; max repairs 2. A dispatch is durably recorded before
any external handoff. Restart preserves ACTIVE work without launching it again.
Exact-once external process execution is NOT claimed. Unknown/expired executions
block until explicit retry. Replaying a saved result is safe.

## Report envelope (all fields required, unknown fields rejected)

```json
{
  "schema_version": 1,
  "task_id": "TASK_ID",
  "dispatch_id": "DISPATCH_ID",
  "role": "codex",
  "attempt": 1,
  "status": "DONE",
  "summary": "Outcome",
  "basis": ["Concrete source or observation"],
  "suggestions": [],
  "next_action": "Requested next action; scheduler retains authority",
  "data": {}
}
```

Nonempty summary, basis (nonempty strings), next_action required. Suggestions is
a string list, max 3 for PLAN_REVIEW. Status by dispatch:

| kind | status | data |
|---|---|---|
| PLAN / PLAN_FINALIZE | DONE | `{"steps":[{"id":"s1","title":"...","acceptance":["..."],"depends_on":[]}]}` |
| PLAN_REVIEW | DONE | `{}` |
| CONSULT | DONE | `{}`; summary ≤4000 characters, suggestions ≤3 |
| CLAIM | DONE | `{"claims":[{"step_id":"s1","reason":"..."}]}` |
| CHAT | DONE | `{}` or bounded `proposals` / `messages`; see [room contract](chat-v1.md) |
| CODE / FIX | DONE | `{"version":"immutable commit or snapshot identifier","changes":["..."],"known_limits":[]}` |
| ANALYZE | DONE | `{"deliverable":"analysis outcome","evidence":["checkable source or observation"]}` |
| VERIFY | PASS / FAIL | `{"version":"exact dispatch version","checks":[{"criterion":"exact acceptance string","status":"PASS or FAIL","evidence":["artifact reference or concrete command/result"]}],"findings":[]}` |
| any | BLOCKED | `{"reason":"..."}` |

Every acceptance criterion must occur exactly once in verification checks. PASS
requires every check PASS and no findings. FAIL requires at least one FAIL and at
least one finding `{ "problem":"...", "reproduction":["..."], "expected":"...",
"actual":"...", "evidence":["..."] }`. Evidence references are recorded, not
independently authenticated by the scheduler; PASS is a reported verdict.
Known limits cannot alter acceptance. FIX must submit a different version.
ANALYZE output receives a scheduler-computed digest as its version. Failed
analysis verification reissues analysis with the finding in its step context,
at most `max_repairs` times; it does not pretend the API Agent edited code.

Duplicate identical report for an already accepted dispatch returns
`{"accepted":true,"duplicate":true}` without new events. Different result for
that dispatch: CONFLICT. Wrong task/role/attempt/version: reject, no state change.
Malformed report: INVALID_REPORT. Stale dispatch: STALE_REPORT. Unknown IDs:
NOT_FOUND. Invalid transition: INVALID_STATE. Invalid plan: INVALID_PLAN.

Paused tasks accept already-issued results but remain PAUSED; no new work until
resume. BLOCKED results and timeouts block task and dispatch without counting a
code repair. Explicit retry restores original step activity, gets a new dispatch
ID and attempt. First and second failed verifications schedule FIX 1 and FIX 2;
failure after FIX 2 blocks with REPAIR_LIMIT and cannot be retried via CLI.

## Artifacts and boundaries

SQLite is authoritative. JSON/Markdown files are handoff artifacts, never trusted
as commands. No shell evaluation of model output. `template` emits JSON to stdout;
caller may save it to a file. Evidence and Markdown can live beneath a task-specific
artifact directory. Git dirty status is diagnostic, not an automatic reset/cleanup.
Manual mode, durable runtime sessions, bounded automatic jobs and a browser UI
are implemented. Simulated tests validate orchestration, not real-provider access.
Worktree isolation and same-task cost comparisons remain unimplemented/unverified;
see [backlog](../next-steps.md) and [recorded evidence](../../qa/group-room/acceptance.md).

## HTTP transport

This is a **local trusted-operator API**, not an authenticated multi-user service.
The server binds to loopback, checks Host, rejects cross-site requests and requires
a matching HTTP Origin when present. These checks do not isolate local processes.
No wildcard CORS or arbitrary executable request parameter.

Nonempty POST bodies must be JSON objects with `Content-Type: application/json`;
empty bodies become `{}`. Maximum body size: 5 MiB. Trailing slashes are removed.
Table paths exclude query strings. `?` denotes optional fields. Unknown-field
rejection is route-specific, **not** a global guarantee.

Errors: `{"error":{"code":"...","message":"..."}}`. NOT_FOUND → 404;
CONFLICT / ALREADY_STARTED / INVALID_STATE → 409; other domain/input errors → 400
(including APPROVAL_REQUIRED and PAYLOAD_TOO_LARGE). Origin/Host guards and
disallowed artifact filenames → 403; wrong content type → 415; unexpected errors
→ 500. Local OPTIONS returns 204; unknown API routes return 404.
202 means persisted/reserved, not successful model execution. Never automatically
replay a failed/unknown POST that may consume quota or change files.

### Health and Agent objects

`/health.version` is currently `v1.2`, not schema negotiation. `features` contains
`task-teams`, `bounded-team-discussion`, `delegate-team`, `deepseek-harness`,
`project-context`, `project-memory`, `file-references`, `per-message-write`,
`project-diff`. This is not an exhaustive capability list. `providers` contains
startup Codex/Antigravity discovery, not live authentication/quota for all Agents.

Public Agent fields: `id,name,type,base_agent,executable,endpoint,model,api_key_env,
roles,color,avatar,description,system_prompt,enabled,ready,writable,has_key,has_stored_key`.
No plaintext key is returned. `ready` is configuration-level availability, not
authentication or tool-access proof. `writable` means adapter write-mode support,
not a current turn grant. Antigravity actual safe writing remains unverified.
Room membership is pinned per user message chain; new chats default read-only.
The current chat response additionally exposes available_members; message outputs
include room_members, write_epoch and derived write_authorized. These are not
client-settable fields. See the room contract for irreversible revocation of old
write grants and the distinction between queued and already-running processes.

Registration ID: `[a-z][a-z0-9-]{0,63}`; built-in IDs cannot be replaced.
Use `type:"cli"` with `base_agent` codex / antigravity / deepseek-harness, or
`type:"openai_compat"` with `endpoint` and `model`. CLI clones inherit supported
adapters, not arbitrary executables. API base URLs require HTTPS (HTTP only on
loopback), no userinfo/query/fragment, and no `/chat/completions` suffix.
Optional `api_key_env` names an environment variable; `secret_key` stores a local
key in plaintext `secrets.json` beside the DB (created with mode 0600).
Environment variables take priority. Each GET /agents checks file metadata and
returns secret_storage: status missing / owner_only / warning / unknown; mode is
an octal string or null; warnings contains `{code,message}`. Codes include
UNEXPECTED_MODE (not 0600), OTHER_OWNER, SYMLINK, NOT_REGULAR, CHECK_FAILED and
UNSUPPORTED. Checks do not follow symlinks, return keys, or change permissions.
owner_only checks POSIX mode/owner, not ACLs, encryption or past disclosure.
This is a warning, not a new credential-use block; existing loading behavior is unchanged.

Profile patch fields: `name` (1–100), `description` (≤300), `system_prompt` (≤4000),
`color`, `avatar`, `secret_key`; only API Agents apply `endpoint` and `model`.
Empty secret_key clears the stored key, not an environment variable. Unknown
profile fields are currently ignored, not rejected. HTTP delete defaults
cancel_queued to true; eligible unsent work can be cancelled, not active processes.
Built-ins cannot be deleted; missing custom IDs return false. Deletion removes
stored secrets and leaves a tombstone to prevent default-template reappearance.

### Workspace data and destructive operations

`/files`: at most 250 entries; size is bytes, total is returned count, not the
whole repository count. `/file`: at most 12000 bytes decoded UTF-8 with replacement;
missing, unreadable or outside-workspace paths return 404. This is not a secret
content filter. Memory lives in the DB, ≤20000 characters; append inserts a newline.

`/diff` includes Git status and tracked-file diff against HEAD (≤131072 bytes).
Untracked paths may appear without their content in diff. Non-Git projects return
is_git:false. `/revert-file` **discards local staged/unstaged changes** to a tracked
path back to HEAD, or deletes an untracked file; no automatic backup. The UI
confirms, but the API has no confirmation token. Do not call it as a preview.
Project/task deletion removes platform records, not project source directories.
In-flight run guards exist; chat-worker deletion races remain a backlog item.

Artifact access accepts only prompt.txt, command.json, events.jsonl, stderr.log,
result.json and a 32-character hexadecimal run ID. Previews are ≤512 KiB; oversized
events/stderr show the tail, all other cases show the head. Artifacts can contain private data.
