# WorkTogether 原生客户端新版

日期：2026-11-12。此版本基于 AO 独立源码分支，不是原 Python/Web 服务的换肤；原应用、原数据库和官方签名 AO 均保留。

## 操作顺序

1. 双击仓库的 `scripts/launch-native-desktop.command`，启动 `~/Applications/WorkTogether Local.app`。入口会把已安装 Codex 与 DeepSeek Harness 的命令目录加入该进程的搜索路径，不改全局配置。这是本机源码构建，未做 Apple 公证或公开发布。
2. 打开你的 Git 项目，切到「项目群聊」，点击右上角「添加成员」。分别填写人数，例如 Codex 2 人、DeepSeek 1 人。也可以先勾选已有会话，再添加新成员。
3. 点击「添加 3 位成员」。平台创建独立的原生 Chat 会话，达到两位后直接保存进房间，无需先给每位 Agent 发一条任务。只添加一位且没有其他已选成员时会提示继续添加；房间最多 16 人。找不到本机客户端时该选项不可添加；未知登录状态仍需在创建时验证。创建会启动原生客户端，但不提交初始任务；不要将其理解成保证第三方客户端完全不联网。部分失败会停止后续创建并保留已成功的会话，不自动重试。
4. 手动勾选已有成员后，会显示「待加入／待移出 · 未保存」。点击成员列表上方「保存选择」才会改变接收人；未保存时禁止连接工具、暂停/恢复及群聊发送，保存失败保留选择。发现房间版本已变化时需先载入已保存成员再修改，避免覆盖他人的修改。
5. 输入框底部展示成员图标与名称。点击「＋」添加成员，点击成员可重命名、选择原生客户端实际提供的模型和推理强度；不可用成员带提示标记，点开可查看原因及原生会话入口。点击上箭头或 Enter 发送新消息，Shift+Enter 换行。只发给可用成员，停止成员不会自动恢复或补发。发送同时连接当前房间同伴工具；读取不会自动续权。「房间设置」中保留成员选择、任务和投递上限。
6. 新消息附带房间、自身会话编号、本次接收人名单及协作工具说明，成员可按需要提问、认领和交叉验收。界面逐成员展示投递结果和精确关联的原生回复。投递成功不等于任务完成；失败或不确定结果不会自动重发。
7. 成员使用 `peer_tasks` 查看房间与任务，使用 `peer_task` 提出、认领、提交、独立验收任务，使用 `peer_send` 与同伴沟通。任务面板展示负责人和证据；用户也可添加待认领目标，不强制指定某类 Agent 做某项工作。
8. 输入框的「访问权限」按成员设置审批策略。Codex 提供「请求批准／帮我批准／完全访问权限」；其他客户端只展示其支持的模式，不强行等同语义。选择后需点击「应用权限」，仅影响该成员后续操作，打开菜单不会改变权限。实际操作审批仍在原生会话处理。全部任务经其他成员验收后，可在「生成候选版本」生成独立候选分支；不会自动合并主分支，仍需最终集成测试。

## 数据与边界

- 新广播使用持久化 `broadcastId` 合并展示一次用户消息，回复分别标记成员名称与状态。旧记录没有该字段，不按相同文字或时间猜测合并。投递次数留在房间设置，不冒充访问权限。

- 本地新版默认使用 `~/.ao/worktogether-local/`，不会自动读取旧 WorkTogether SQLite 或官方 AO 会话；显式 AO_DATA_DIR / AO_RUN_FILE 仅供隔离验证。
- 本地构建没有在线发行服务：启动、手动检查、下载和安装更新入口均已关闭。设置页明确显示「本地构建」，不再把没有发布版本当作更新失败。后续通过本地重新构建安装更新。
- 同伴消息仍受成员、项目、房间版本和投递预算校验。相同客户端可以有多个独立会话；账号额度仍可能共用。
- 任务修改采用版本校验，禁止自行验收；工作树隔离不等于操作系统沙箱。当前信任本机进程，不宣称可抵御恶意本地进程冒充身份。
- 历史回复按 `client_message_id → conversation_turn → assistant message` 关联，不按文本相似或时间推断；旧投递无关联键时不猜测补齐。每次投递最多展示 100 条助手消息，更多内容提示前往原生会话。
- 已真实验证 Codex 与 DeepSeek 同时接收新消息、识别彼此、各发送一次同伴核验请求、分别认领并交叉验收只读任务。实际桌面 Enter 发送及双成员回复更新已验证，见 [验收证据](experiments/native-room-flow-verification.json)。停止成员未收到测试消息，旧失败记录未重发。这不代表任意真实项目已能无人值守交付。
- 任务依赖图、取消/重新认领、自动最终集成测试与任意编码任务的全链路真实模型验收仍未完成。

## 源码复现

独立源码在 `~/Applications/worktogether-evaluation/source`。基线 `033d597032e448a0ea16c298350e36b099f74106`，先应用 `experiments/ao-scoped-peer-mcp.patch`，再按编号应用 `experiments/0001-*.patch` 等后续补丁。不得在已有补丁的工作树重复应用。MIT 上游版权与许可证保留。

安装依赖后，前端打包使用项目准备的 Node 22，避免本机 Node 26 下 Electron zip 解压未完成却退出的情况；`frontend/scripts/build-tmux.mjs` 已禁用新 SDK 误探测的 pipe2，使用兼容实现。使用本机测试数据库和假发送器验证，不需要真实模型配额。

详尽测试结果及源码提交见 [评估记录](ao-evaluation.md)。
