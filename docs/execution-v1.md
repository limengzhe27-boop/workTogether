# 2026-09-22：保留现有内核，优先补自动执行

决策：继续完善 WorkTogether，不迁移 AO。已有任务协议、报告校验、审批和有限规划可以复用；AO 是不同技术栈的完整产品，Antigravity 验收器主分支明确标为实验性且不是操作系统隔离。迁移不能省掉我们的验收权限与轮次约束。AO 的隔离后台已验证能启动，并报告两个 CLI 已安装/已授权；未进行真实双 Agent 调用，不能宣称完整协作通过。

本次实现的是命令行自动执行第一版，不是完成整个桌面应用：

1. 使用 `python3 -m worktogether --db PATH approval --task ID` 查看方案及摘要。
2. 用户核对后，使用 `execute --task ID --approve-digest DIGEST --max-calls 6`，并指定两个 CLI 的 executable 路径（数据库参数同上）。
3. 顺序运行 CODE → VERIFY → 必要的 FIX；报告仍由原状态机校验，最多两次修复。
4. 每次调用前检查审批、暂停、排队消息、已有派发。工具失败不自动重试；达到调用上限就停止，需显式再次执行。
5. 同一任务的自动执行使用进程锁；进程异常后，已有派发仍阻止自动重放。锁文件留在数据库旁，不含任务正文。

验收：新增模拟测试覆盖正常完成、调用预算、审批缺失、暂停、工具失败、返工熔断、消息插入、非法预算。不调用真实模型。

限制：macOS/Linux；尚无后台自动恢复。暂停不强行中断正在执行的工具；当前调用返回后不再推进。不要同时用手动派发控制同一任务。Antigravity sandbox/plan 不是可靠的只读权限；真正并行验收需后续增加独立被测版本工作区。

## 网页接入

已批准的计划显示“自动开发与验收 · 最多 6 次调用”。POST `/api/tasks/ID/execute` 接受空对象，固定调用预算为 6，每次超时 300 秒；不接受客户端指定可执行程序。GET `/api/tasks/ID/execution-jobs` 返回持久化作业。未批准、已有派发或未结束作业会拒绝启动。

作业完成仅表示调度本轮停止，不代表任务验收成功；页面根据 result.reason 区分 COMPLETED、CALL_LIMIT、消息插入、任务暂停等。刷新只读状态，不发起执行。重启后的 QUEUED/RUNNING 保留，禁止自动重放，暂需人工核对处理。单任务自动作业会禁用网页手动运行按钮，暂停按钮保持可用。

验证范围：后端模拟测试与前端 TypeScript/生产构建；本轮没有浏览器交互验收，也没有真实模型端到端调用。

## 保守恢复入口

网页增加“检查并解除讨论/执行等待”。POST `/api/tasks/ID/{planning|execution}-jobs/JOB/recover` 接受空对象。调度工作线程持有跨进程作业锁；恢复必须取得同一锁，并确认没有 ACTIVE 派发、PREPARED/RUNNING/EXITED 模型记录，才将旧作业标记为 INTERRUPTED 并记录 JOB_RECOVERED 事件。重复恢复幂等，恢复后不启动模型。已被恢复的排队线程即使延迟启动，也不会执行。

此入口不处理可能存活的模型进程，不强制清除未知结果；遇到这类记录会拒绝恢复，仍需检查运行日志并使用已有命令行收集/确认停止机制。部署升级应先停止旧服务，不可与缺少作业锁的旧版本同时运行。

## 离线隔离执行第一阶段（2026-10-12）

这是独立的、实验性的本机 Python 执行器，不改变上面的 Agent 调度或授权。网页/API/Agent 尚不能调用它；没有提供任意 shell、可执行程序、环境变量、挂载或自定义沙箱规则的输入。

### 入口与输出

`python3 -m worktogether isolation-check` 仅使用临时假文件自检；`isolated-python --project-path PATH --file test_example.py --file example.py --entry test_example.py --timeout 10` 将明确选择的文件复制后执行入口。测试入口需自行调用测试运行器（例如 `unittest.main()`），不自动发现整库测试。全局 `--db PATH` 仅用于排除状态目录，不初始化数据库、注册 Agent 或调用模型。

- 最多 10 个显式相对文件、每个最多 1 MiB，必须是完整 UTF-8 文本；拒绝隐藏/常见凭据路径、状态目录、符号链接、多硬链接、特殊文件和越界。按打开的目录描述符逐层读取，并为副本返回 SHA-256。
- 副本按次创建、执行后删除，不读取生成文件、不回写原项目、不提交 Git。多文件读取不是原子快照，不代表固定 Git 提交；原项目的外部并发编辑不由它阻止。
- JSON 返回 `status`、`reason`、退出码、受限 stdout/stderr、输入摘要与自检结果。`COMPLETED` **只表示子进程退出码为 0**，不证明输出中的 PASS 真实可靠；输出按不可信内容处理。拒绝或执行失败返回非零 CLI 状态，不重试。

### 操作系统边界

- 当前仅 macOS `sandbox-exec` + 专用目录内的 Python 运行时；框架 Python 直接启动解释器，避免为启动器放开子进程。使用参数传路径，不拼接 shell/Scheme。未知平台/运行时/沙箱错误均拒绝，无宿主执行降级。
- deny-default 策略仅放行系统动态加载规则、系统库、Python 运行时读取和临时工作目录读写；不导入较宽的 `system.sb`，不放行网络、常规 IPC 或子进程。Python 使用 `-I -S -B`，不加载用户站点包或环境钩子。与系统/运行时读范围重叠或包含临时根目录的项目拒绝执行；系统/运行时目录并非机密隔离区，不要在那里存放秘密。
- 每次运行前用固定脚本验证副本读写、外部假文件拒读/拒写、符号链接绕出、硬链接、TCP 连接/监听、Unix socket、fork/子进程、环境清理；任一不符即拒绝。这只能验证所列行为，不能证明不存在 OS 或配置漏洞。
- 不继承宿主环境，仅给临时 HOME/TMPDIR、固定 PATH/locale；关闭额外句柄，stdin 为空。程序执行前施加硬限制：core dump 为 0、单文件 1 MiB、打开句柄 64、CPU 30 秒。默认墙钟 10 秒、最大 30 秒；同时流式读取两个输出通道，合计 64 KiB，超时/超量终止并回收进程，不无限缓存输出。
- **不是 VM 或完整资源容器**：没有总磁盘、内存、线程数硬配额，写出许多小文件或快速分配内存仍有宿主资源风险。仅适合明确选择的小型离线测试；不得因此开放自动 Agent 命令工具。未来需补资源隔离、明确测试命令契约、写授权复查、项目占用与受审查回写。
- `sandbox-exec` 在本机系统手册中标记 DEPRECATED，Apple 的私有加载规则可能变化；升级后必须重新通过自检。设计参考 [Chromium 的原生沙箱说明](https://github.com/chromium/chromium/blob/main/sandbox/mac/seatbelt_sandbox_design.md) 的默认拒绝及最小资源原则，未复制其配置，也不宣称具备同等安全保证。

### 无模型验证

`tests/core/test_isolation.py` 包含配置/输入/输出限制、失败不降级、临时副本清理和真实原生沙箱测试。`WT_REQUIRE_ISOLATION_TESTS=1` 要求原生检查真实执行；外层开发沙箱禁止嵌套时，普通测试明确跳过，严格模式则失败。GitHub Actions 已加入 macOS 专项作业，远端实际运行仍待推送后验证；本地证据见 roadmap。
